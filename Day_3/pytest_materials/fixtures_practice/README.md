# Практика pytest: фикстуры

Решение упражнения из 12 пунктов. Основной файл — `test_fixtures.py`:
три фикстуры предоставляют кортеж, список и словарь, а шесть тестов проверяют
их структуру и значения. Два дополнительных файла сохраняют предыдущие
этапы упражнения, чтобы сравнить вывод без ручного переписывания решения.

## Файлы и этапы

| Файл | Этап | Количество тестов |
|---|---|---:|
| `test_fixtures_function.py` | `return`, scope по умолчанию: `function` | 2 |
| `test_fixtures_module.py` | Та же фикстура и два теста, но `scope="module"` | 2 |
| `test_fixtures.py` | Итог: `module` + `yield`, зависимые список и словарь | 6 |

Все файлы самостоятельные: одинаковые имена фикстур в разных модулях
не означают общий экземпляр на весь набор. Для этого упражнения
`conftest.py`, `__init__.py`, пакет `tasks` и дополнительные плагины не нужны.
Используются обычные функции, `assert` и pytest.

## Выполнение пунктов упражнения

### Пункты 1–4: данные и использование

В итоговом файле `sample_tuple`, `sample_list` и `sample_dict` предоставляют
данные. Для каждой есть тест, а `test_tuple_structure` и `test_tuple_content`
явно запрашивают одну и ту же фикстуру `sample_tuple`.
Список и словарь зависят от кортежа; pytest сам разрешает зависимости.

### Пункт 5: scope по умолчанию

```powershell
python -m pytest --setup-show test_fixtures_function.py
```

Найдите два `SETUP F sample_tuple`: фикстура готовится отдельно для каждого
из двух тестов. `F` означает `function`. Видны также два `TEARDOWN F`,
хотя в return-фикстуре нет написанного нами кода завершения.

Ответ на вопрос «Все ли фикстуры запускаются перед каждым тестом?»:
нет, только запрошенные тестом (в том числе через зависимости) или
автоматические `autouse`-фикстуры. Запрошенная function-фикстура выполняется
для каждого теста; более широкие scope переиспользуются в своей области.
В данном упражнении своих `autouse`-фикстур нет.

### Пункты 6–7: scope module

```powershell
python -m pytest --setup-show test_fixtures_module.py
```

Теперь виден один `SETUP M sample_tuple`, общий для двух тестов, и один
`TEARDOWN M`. `M` означает `module`. Фикстура создаётся при первом запросе,
а не обязательно при самом импорте файла.

### Пункты 8–10: yield и завершение работы

```powershell
python -m pytest --setup-show test_fixtures.py
python -m pytest -s -v test_fixtures.py
```

В итоговом файле используется `yield` вместо `return`.
Сообщение `SETUP sample_tuple` выводится один раз перед первым тестом.
После `yield` выполнение фикстуры приостанавливается, и тесты получают кортеж.
Сообщение `TEARDOWN sample_tuple` появляется после последнего использующего
её теста в модуле. Флаг `-s` отключает перехват вывода, поэтому видны `print`;
`-v` показывает имена и результаты тестов.

Общий кортеж не меняется в тестах. Список и словарь создаются заново
для каждого теста: изменения не переносятся между тестами.
Для этих данных очистка внешнего ресурса не нужна, поэтому после `yield`
стоит только демонстрационное сообщение, а не искусственная «очистка».

### Пункты 11–12: список и описание фикстур

```powershell
python -m pytest --fixtures
python -m pytest --fixtures -v test_fixtures.py
```

Первая команда показывает доступные фикстуры, включая встроенные.
Во второй удобнее искать фикстуры итогового файла и их docstring:
`sample_tuple`, `sample_list`, `sample_dict`.
Описание оформлено строкой документации внутри функции, а не только
комментарием `#`, чтобы pytest мог показать его в справке.
Дополнительные фикстуры от установленных плагинов — нормальное явление.


## Быстрая проверка

```powershell
python -m pytest -v test_fixtures.py
python -m pytest -v test_fixtures_function.py test_fixtures_module.py test_fixtures.py
```

Ожидается 6 пройденных тестов в основном файле и 10 во всех трёх.
